# AI 협업규칙

이 파일은 **사용자가 선택한 Obsidian 보관함** 안에 둡니다. 사람과 AI가 함께 읽는 정리 약속입니다. 처음에는 **1번의 폴더 구조**를 확인하세요. 2·3번은 AI가 할 일이고, 4번은 나중에 내 방식으로 바꾸는 방법입니다.

## 1. 우리의 폴더 구조

사용자가 AI 전용 폴더를 직접 만듭니다. 이름과 저장 위치는 사람마다 다릅니다.

```text
사용자의 AI 전용 폴더/
├─ AGENTS.md·CLAUDE.md    ← 처음 연결할 때 AI가 준비하는 시작 안내
├─ 프로젝트 폴더들/       ← 원본 자료와 결과물
└─ 사용자의 Obsidian 보관함/
   ├─ AGENTS.md           ← 내려받은 보관함 작업 안내
   ├─ CLAUDE.md           ← 내려받은 Claude Code 안내
   ├─ AI협업규칙.md       ← 이 문서
   ├─ 홈.md               ← 소개 노트로 가는 목차
   └─ 프로젝트 소개·기록 노트
```

**기본 폴더 구조는 다음과 같이 유지합니다.**

- 프로젝트 원본 폴더들과 공통 Obsidian 보관함은 AI 전용 폴더 안에 나란히 둡니다.
- 목차를 만들 때 원본을 보관함으로 옮기거나 복사하지 않습니다. 새 보관함이나 원본 복제 방식도 임의로 만들지 않습니다.
- AI 전용 폴더 전체를 보관함으로 바꾸지 않습니다. 이미 바깥에 있는 코드 등의 원본도 제자리에 두고 위치만 연결합니다.

“원본도 Obsidian에서 읽고 싶어”라는 말만으로 원본을 옮기거나 복사하지 않습니다. 현재 구조에서 링크로 여는 방법을 설명합니다. 실제 폴더 구조 변경을 원하는지는 별도로 확인합니다.

처음 연결 설정을 요청하면 AI 전용 폴더에도 짧은 AGENTS.md·CLAUDE.md가 생길 수 있습니다. 이 두 파일은 보관함의 규칙을 찾아 읽으라는 시작 안내입니다. 내려받은 규칙 3개의 자리는 보관함 안에 유지합니다.

## 2. “목차에 연결해 줘”라고 요청받으면

1. 원본 폴더와 기존 보관함 위치를 실제로 확인합니다. 보관함의 홈과 관련 프로젝트 소개 노트를 먼저 읽습니다. 위치나 소속이 불분명할 때만 필요한 내용을 묻습니다.
2. 기존 소개 노트가 있으면 이어 씁니다. 새 노트는 기존 분류를 따릅니다. 처음 정리하는 보관함이면 `10 프로젝트/프로젝트 이름/프로젝트 이름.md`를 기본 자리로 사용합니다. 폴더 이름의 프로젝트 이름 부분은 실제 요청에 맞춥니다.
3. 소개 노트에 **무슨 프로젝트인지 / 현재 상태 / 다음 할 일 / 원본 자료 위치**를 짧게 적습니다. 모르는 내용은 미확인이라고 적습니다.
4. 홈.md에 소개 노트로 가는 내부 링크를 한 번 넣습니다. 홈이 없고 다른 목차도 없다면 홈.md를 만듭니다. 기존 목차 이름이나 분류는 임의로 바꾸지 않습니다.
5. 소개 노트에 “AI 전용 폴더 → 북부대공”처럼 찾아갈 순서를 글로 적고, 이 컴퓨터에서 여는 원본 폴더·파일 링크도 만듭니다. 다른 PC에서는 주소가 달라질 수 있음을 짧게 표시합니다. 사용자가 제공한 GitHub 같은 웹 원본 주소도 링크합니다. 외부 파일은 기본 연결 앱에서 열릴 수 있습니다.
6. 원본이 제자리에 있는지, 소개 노트가 실제 저장됐는지, 홈 링크의 대상이 존재하는지 확인합니다. 새로 만든 파일과 수정한 파일의 위치를 짧게 알려 줍니다.

**누가 하는 일인지 구분합니다.** 사용자가 자료를 저장하고 AI에게 정리를 요청합니다. AI가 소개 노트와 목차 문서를 작성합니다. Obsidian은 보관함 안의 변경을 화면에 표시합니다. 외부 원본 본문이 자동으로 보관함에 들어오거나 검색된다고 설명하지 않습니다.

## 3. 프로젝트 작업을 마칠 때

- 의미 있는 작업이 끝나면 소개 노트의 현재 상태·다음 행동·원본 위치를 갱신하고 목차 연결을 확인합니다. 매번 같은 정리 요청을 다시 하게 만들지 않습니다.
- 기존 작업기록.md가 있으면 그 방식을 유지하고 소개 노트에서 연결합니다. 기록 방식이 아직 없고 작업이 길어지면 같은 프로젝트 안에 날짜별 상세기록을 둡니다. 완료한 일, 확인한 것, 미확인 사항, 다음 행동을 적습니다.
- 이미 적힌 내용을 읽고 필요한 부분만 수정합니다. 다른 AI가 수정 중임을 알게 된 파일은 동시에 고치지 않습니다. 이 규칙이 자동으로 파일을 잠가 주지는 않습니다.
- 자료를 받기만 해도 자동 등록된다고 약속하지 않습니다. 이 규칙은 **AI가 관련 작업을 맡아 실행하는 동안** 적용됩니다.

## 4. 앞으로 내 방식으로 바꾸기

사용자는 AI와 대화하며 소개 노트의 항목, 문장 길이, 목차의 분류, 기록 빈도를 바꿀 수 있습니다. 예: “소개 노트에 마감일도 넣어 줘”, “개인 작업과 공부를 목차에서 나눠 줘.”

“앞으로”처럼 계속 적용해 달라는 변경만 이 파일에 짧게 반영하고 바뀐 줄을 알려 줍니다. 이번 작업에만 적용하는 조건은 공통 규칙으로 만들지 않습니다. 계속 적용할지 불분명할 때만 묻습니다. **1번의 폴더 구조는 사용자가 구조 자체의 변경을 명시적으로 요청할 때만** 바꿉니다. 그때는 원본 위치·기존 링크에 생기는 영향을 설명하고 적용 범위를 확인합니다.

## 5. 확인할 수 있는 일만 말하기

- 실제로 읽은 내용과 추정을 구분합니다. 확인하지 않은 완료·성과·사용자 의도를 지어내지 않습니다.
- 개인정보·비밀번호를 공개 자료에 넣지 않습니다. 원본 삭제·대량 이동·외부 공개는 사용자의 지시 범위를 확인합니다.
- 로컬 폴더 접근이 없으면 가능한 안내와 불가능한 저장을 구분합니다. 일반 채팅에 파일을 첨부한 것만으로 컴퓨터의 홈.md를 고쳤다고 말하지 않습니다.
