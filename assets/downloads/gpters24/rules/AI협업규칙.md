# AI협업규칙

이 파일은 **사용자가 선택한 Obsidian 보관함 안**에 둡니다. 사람과 AI가 함께 읽고 고치는 정리 약속입니다. 폴더 이름과 저장 위치는 사람마다 다릅니다.

## 1. 우리의 폴더 구조

```text
사용자의 AI 작업 폴더/          ← 이름은 직접 정해요
├─ AGENTS.md                 ← AI가 보관함 규칙을 찾는 시작 안내
├─ CLAUDE.md                 ← Claude Code의 시작 안내
├─ 프로젝트 이름/             ← 프로젝트마다 원본 폴더 하나씩
└─ 사용자의 Obsidian 보관함/
   ├─ AI협업규칙.md           ← 이 문서
   ├─ 홈.md                   ← 소개 노트로 가는 목차의 예시
   └─ 프로젝트 소개·기록 노트
```

- 프로젝트 원본 폴더들과 **공통 보관함 하나**를 AI 작업 폴더 안에 나란히 둡니다. 이미 AI 작업 폴더 밖에 있는 원본도 제자리에 둡니다.
- 보관함에는 원본을 설명하는 노트와 목차를 둡니다. 목차를 만들기 위해 원본을 옮기거나 복사하지 않습니다.
- AI 작업 폴더 전체를 보관함으로 바꾸거나 보관함을 새로 만들지 않습니다. 구조 변경은 사용자가 명시적으로 요청할 때만 검토합니다.
- 이미 다른 규칙 파일이 있다면 바로 덮어쓰지 않습니다. 기존 파일을 읽고 필요한 내용만 제안한 뒤 사용자의 확인을 받아 반영합니다.

## 2. “목차에 넣어 줘/연결해 줘”라고 요청받으면

1. 원본 폴더와 현재 사용하는 보관함의 위치를 확인합니다. 기존 홈/목차와 관련 소개 노트가 있는지 읽습니다.
2. 소개 노트가 있으면 이어 씁니다. 없으면 기존 분류에 맞춰 만듭니다. 분류가 아직 없다면 `10 프로젝트/프로젝트 이름/프로젝트 이름.md`를 예시로 쓸 수 있습니다.
3. 소개 노트에 **무슨 프로젝트인지 / 현재 상태 / 다음 할 일 / 원본 위치**를 짧게 적습니다. 모르는 정보는 지어내지 않습니다.
4. 기존 홈/목차에서 소개 노트로 가는 내부 링크를 만듭니다. 목차가 하나도 없다면 `홈.md`를 만듭니다.
5. 원본 폴더를 찾는 방법과 확인된 링크를 소개 노트에 적습니다. 다른 컴퓨터에서는 로컬 주소가 달라질 수 있음을 알려 줍니다.
6. 원본이 제자리에 있는지, 소개 노트가 저장됐는지, 홈 링크가 열리는지 확인하고 변경한 파일을 알려 줍니다.

**사용자가 원본을 저장하고 AI에게 정리를 요청합니다.** AI가 보관함의 소개 노트와 목차를 작성하면 Obsidian이 그 변경을 화면에 보여 줍니다. Obsidian은 보관함 밖의 MD 본문을 자동으로 검색하거나 추적하지 않습니다.

## 3. 프로젝트 일을 마칠 때

- 의미 있는 작업이 끝나면 관련 소개 노트의 현재 상태·다음 행동·원본 위치와 홈 링크를 확인합니다. 자료를 받기만 해도 자동으로 등록된다고 약속하지 않습니다.
- 기존 기록 방식이 있으면 유지합니다. 없고 작업이 길어지면 소개 노트와 분리된 상세기록을 만들 수 있습니다.
- 다른 AI가 같은 파일을 수정 중이면 동시에 고치지 않습니다. 이 규칙이 파일을 자동으로 잠그지는 않습니다.

## 4. 나중에 내 방식으로 바꾸기

소개 노트의 항목, 목차 분류, 기록 빈도는 AI와 대화하며 바꿀 수 있습니다. “앞으로 소개 노트에 마감일도 넣어 줘”처럼 계속 적용할 약속만 이 파일에 반영합니다. 이번 작업에만 필요한 조건은 공통 규칙으로 만들지 않습니다.

## 5. 확인한 일만 말하기

- 읽은 내용과 추정을 구분합니다. 확인하지 않은 완료·성과·사용자 의도를 지어내지 않습니다.
- 개인정보·비밀번호를 공개 자료에 넣지 않습니다. 원본 삭제·대량 이동·외부 공개는 사용자 지시 범위를 확인합니다.
- 로컬 폴더에 접근할 수 없으면 저장했다고 말하지 않습니다. 웹 채팅의 파일 첨부만으로 컴퓨터의 `홈.md`가 바뀌지는 않습니다.
